# MLAstroRPA+TPPA v2.2.0.0

Feature release — the dock header now shows the device network path (AP / STA) next to the status, exactly like the Web UI header.

**Requires device firmware 1.7.0 or newer for the full information** (older firmware still works — see Notes)

## ✨ Highlights
- **`AP:` row** — `connected <IP>` when this PC reaches the device through its own hotspot, `ready <IP>` when it goes through the router (or the USB cable), `error` when the hotspot did not come up
- **`STA:` row** — `📶` internet · `📶!` joined the router but no internet · `📶x` not joined, followed by the LAN IP assigned by the router
- **Clean header while disconnected** — the AP/STA rows and the firmware version stay hidden until the device is connected and the handshake succeeded
- Plain lowercase text, same font/size/colour as the `STA:` label; the old `Connection:` line is gone

## 🔧 Changed / Fixed
- New telemetry handling: token `WQu` plus WebSocket fields `link` / `ap_ready` / `ap_ip` / `sta_qual` / `sta_ip`; the STA IP from telemetry is kept fresh (it used to come only from the cached config snapshot)
- **Save All & Reboot over Serial now really reboots**: the plugin sends the settings, waits for the device's `All Setting Saved` line and only then resets the ESP32 over DTR/RTS. Before, it waited 1 s and assumed the device rebooted itself — but the firmware intentionally does not self-reboot, so nothing happened (settings were still written to FRAM, the reboot just never occurred)

## ⚠️ Notes
- With firmware older than 1.7.0 the device does not report `ap_ready` / `sta_qual`: the `AP:` row then shows `error` and `STA:` falls back to the RSSI level — everything else behaves as before
- Works over both Serial (COM) and Wireless; no protocol change for the MLAstro driver or the TPPA paths
